# Імпорт HH у спільну базу

Виконано за `1.md`, `2.md` та фактичною схемою PostgreSQL `public`.
Локальний `database/schema.sql` не застосовувався. Таблиці й обмеження
спільної бази не змінювалися.

Імпортер: `vacancy_parser/shared_import.py`.
Джерело — `data/hh_fast/full_cards.jsonl`, додаткові маршрути та метадані
знімків — `data/hh_fast/queue.sqlite3`, відкритий лише для читання.
HTML не завантажується, не розпаковується й не архівується під час імпорту.

Підключення береться з локального `.env`. JDBC-адреса PostgreSQL також
підтримується. Секрети не входять у звіти; `.env` включений у `.gitignore`.

```powershell
# Додаткові залежності для PostgreSQL-імпорту
uv pip install --python .\.venv\Scripts\python.exe -r requirements-import.txt

# Завантаження або повторний запуск тієї самої вибірки без дублів
.\.venv\Scripts\python.exe -m vacancy_parser.shared_import --run

# Перевірка перенесених полів без запису в БД
.\.venv\Scripts\python.exe scripts\verify_shared_import.py
```

Пакети по 5 000 карток фіксуються окремими транзакціями. Ключ вакансії —
`(source='hh', external_id)`. Попередні класифікаційні прогони не видаляються.
Повторний запуск того самого експорту продовжує власний прогон і не додає
повторні докази для вже завершених класифікацій.

Не імпортуються короткі записи `index`, контактні колонки, вигадані ІПН,
координати чи зіставлення з підприємствами. Рівень `confirmed` не призначався.
Немає вихідної класифікації роботодавців — вона також не вигадується.

Результати перевірки — у `outputs/hh_shared_import/report.json` та
`field_verification.json`. Звіт для власника — `OWNER_REPORT.md` у тій самій
папці. `vacancy_snapshot` містить наявні посилання, час і SHA-256 із checkpoint;
HTTP-статус залишений `NULL`, оскільки окремої колонки статусу в checkpoint
немає. Корінь зберігання джерела власник БД налаштовує окремо; імпортер не
пише в `vacancy_source`.

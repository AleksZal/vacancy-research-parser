# Збір та аналіз вакансій

Проєкт збирає відкриті вакансії HH, зберігає повні картки та HTML і відбирає
кандидатів для дослідження підприємств ВПК РФ. Подальші етапи — перевірка
юридичних осіб, зіставлення вакансій із компаніями та сайт із картою.
Пошукові ознаки не є підтвердженням військової діяльності роботодавця.

## Структура

```text
Парсинг/
├── vacancy_parser/             # Реалізація збирачів і розбору даних
│   ├── hh_fast.py               # Поточний збирач із продовженням черги
│   ├── hh_bulk.py               # Основна черга, завантаження, експорт
│   ├── hh_web.py                # Розбір HTML списків і повних карток
│   ├── hh_pipeline.py           # Пошуки, класифікація, конфігурація
│   ├── hh_expand_scope.py       # Побудова розширеної вибірки офлайн
│   ├── collect.py               # Попередні API/FKC адаптери й спільні функції
│   ├── parse_rostvertol.py      # Попередній адаптер збереженого HTML
│   └── paths.py                 # Стабільні шляхи проєкту
├── configs/                    # Конфігурації, без секретів
│   ├── hh_config.json          # Початкова вибірка
│   ├── hh_expanded_config.json # Поточна розширена вибірка
│   └── scrapling-mcp.example.toml
├── database/                   # PostgreSQL-схема та опис зв'язків
├── docs/                       # Інструкції та історія попередніх запусків
│   └── reference/              # Початкові матеріали хакатону
├── scripts/                    # Допоміжні команди налаштування
├── tests/                      # Автоматичні перевірки без збору з мережі
├── sources/                    # Довідники ГУР/HH, докази, знімки джерел
├── data/                       # Зібрані вакансії, черги та сирий HTML
│   ├── hh_fast/                # Поточна вибірка: SQLite, CSV, JSONL, raw
│   └── hh_bulk/                # Попередній checkpoint і успадкований HTML
├── outputs/                    # Підготовлені звіти, Excel та інші результати
├── tmp/                        # Тимчасові експерименти та тестові файли
├── hh_fast.py                  # Короткий сумісний файл запуску
├── hh_bulk.py                  # Інші старі імена .py також збережені
├── requirements.txt            # Залежності для наявного середовища
└── pyproject.toml              # Метадані Python-пакета
```

Файли `.py` у корені лише передають керування пакету `vacancy_parser`.
Редагувати реалізацію слід усередині пакета; другої копії логіки немає.
Віртуальне середовище `.venv`, Chromium `.browser-cache` та тимчасові файли
приховані в провіднику VS Code, але залишаються на диску.

## Продовження поточного збору

Запускати з кореня проєкту. Для наявної розширеної черги використовувати
саме розширений конфіг:

```powershell
.\.venv\Scripts\python.exe hh_fast.py --run --config .\configs\hh_expanded_config.json --limit 150000 --max-requests 150000 --workers 1 --delay 1.5
```

Альтернативний запуск тієї самої реалізації:

```powershell
.\.venv\Scripts\python.exe -m vacancy_parser.hh_fast --run --config .\configs\hh_expanded_config.json --limit 150000 --max-requests 150000 --workers 1 --delay 1.5
```

Одна команда запускає один збирач. Не запускати обидва варіанти одночасно.
`--limit` — сумарний ліміт повних карток зі старими записами, а
`--max-requests` — бюджет запитів цього запуску. Досягнення ліміту або
вичерпання черги може завершити збір раніше. Перевірки доступу HH потребують
ручної дії; жоден режим не гарантує безперервну роботу чи повноту видачі.

Старий аргумент `--config .\hh_expanded_config.json` також працює через
сумісне перенаправлення у `configs/`. Файл тепер фізично лежить у новій папці.
Для нових команд використовувати канонічний шлях вище.

Перевірка доступу, лише коли її попросив збирач:

```powershell
.\.venv\Scripts\python.exe hh_fast.py --manual-check --config .\configs\hh_expanded_config.json
```

Перегляд допомоги не починає збір:

```powershell
.\.venv\Scripts\python.exe hh_fast.py --help
```

## Де шукати результати

У `data/hh_fast/`:

| Файл | Вміст |
|---|---|
| `full_cards.jsonl` / `.csv` | Усі повні картки, включно з review та excluded |
| `vacancies.jsonl` / `.csv` | Кандидати за сильними ознаками або заданими роботодавцями |
| `review.jsonl` / `.csv` | Записи, що потребують додаткової перевірки |
| `excluded.jsonl` / `.csv` | Записи, відсіяні поточними правилами |
| `index.jsonl` / `.csv` | Короткі записи всіх знайдених ID; частина ще без повного опису |
| `queue.sqlite3` | Стан збору, готові картки, пошукові маршрути |
| `raw/` | Збережені відповіді HTML.gz та метадані |

Для NLP та майбутнього імпорту використовувати JSONL, для перегляду — копію
CSV або підготовлений Excel. Не відкривати робочий CSV в Excel під час
експорту: Excel може заблокувати його заміну.
`data/hh_bulk/raw/` теж потрібна: частина поточних карток посилається на
успадковані HTML. Сама зміна структури не переміщує дані чи checkpoints.

## Перевірки

Залежності вже встановлені у `.venv`. Упорядкування не потребує повторного
встановлення Python, бібліотек або Chromium.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -q
```

На новому комп'ютері створити середовище й встановити `requirements.txt`;
для HTML-збирачів також потрібен Chromium Playwright у `.browser-cache`.
Не зберігати токени, cookies або ключі у `configs/` чи коді. `data/`, кеші,
тимчасові файли та результати не включаються до Git.

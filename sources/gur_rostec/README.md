# Підприємства Ростех з джерела ГУР

Джерело: https://war-sanctions.gur.gov.ua/ru/rostec

Дата оновлення, зазначена на сайті: **15.09.2026**. Знімок отримано **05.10.2026**.

Імпортовано **767 юридичних осіб** із публічної схеми Ростех. Усі 64 сторінки переліку перевірені; ІПН та ОГРН присутні в імпорті для **736** записів. Порожні ідентифікатори не вигадувалися.

- `companies.json` — повний реєстр: назви, скорочення, ІПН/ОГРН, ГУР ID, посилання, зв'язки зі схемою, статус зіставлення та знайдені HH ID.
- `companies.csv` — той самий перелік для перегляду таблицею. Ідентифікатори варто імпортувати в Excel як текст, щоб зберегти початкові нулі.
- `hh_employers_added.json` — **48 нових профілів HH**, доданих до кореневого `hh_config.json`.
- `hh_name_matches.json` — **193 можливі відповідності**, включно з тими, що потребують перевірки.
- `manifest.json` — кількість записів, дата та обмеження перевірки.
- `snapshots/` — стиснені HTML сторінок ГУР для перевірки джерел.
- `hh_config_before_gur.json` — налаштування до цього доповнення.

HH ID взяті з уже збережених HTML вакансій. Профіль увімкнено лише за збігу нормалізованої назви та сайту компанії, який також наведено у профілі ГУР. Для соцмереж перевірено конкретний шлях сторінки; загальні сайти холдингів не використовуються як достатній доказ належності дочірнього підприємства. Позначки ліквідації перевірено для відповідностей, які могли бути увімкнені.

Це зіставлення кандидатів, а не підтвердження однакового ІПН у HH та ГУР: HH ІПН не перевірено. ГУР підтверджує присутність юридичної особи у своєму переліку; конкретна вакансія такого роботодавця може бути цивільною. Статус `vpk_status` у вакансіях залишається `unverified`.

Тепер налаштовано **50 роботодавців** (попередні Ростех та Роствертол збережені) і **57 пошукових фраз**, разом **107 початкових пошуків**. Вакансії за HH ID шукаються без текстового обмеження, в області `113` (РФ). Відсів військової служби за контрактом збережено.

Запуск збору після офлайн-додавання черги:

```powershell
.\.venv\Scripts\python.exe hh_bulk.py --run --limit 20000 --max-requests 10000 --workers 1 --delay 1.5
```

Ліміт 20 000 означає загальну кількість повних карток у базі, включно з попередніми 13 460; він не гарантує, що стільки публічних вакансій буде знайдено. Дублікати відсіюються за ID вакансії HH. Експорти та черга залишаються у `data/hh_bulk`.

719 записів реєстру поки не мають підтвердження за назвою та сайтом у наших збережених даних HH. Серед них є й два початкових роботодавці, налаштування яких не змінювалися. Це не означає, що решта компаній не мають профілів чи вакансій на HH.

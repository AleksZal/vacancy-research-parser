# Окремий паралельний збирач HH

> Актуальні команди для вже розширеної черги — у [README](../README.md).
> Конфіги перенесено в `configs/`, реалізацію — у `vacancy_parser/`.
> Приклади нижче без `--config` використовують початкову вибірку; для
> поточної черги додайте `--config .\configs\hh_expanded_config.json`.

`hh_fast.py` зберігає повний текст вакансій і всі атрибути основного парсера.
База і HTML у `data/hh_bulk` не змінюються під час запуску `hh_fast.py`.
Розширення вибірки з акцентом на дрони, балістику та КАБи описане в `HH_EXPANSION.md`.

## Швидкість

За замовчуванням: до **4 одночасних запитів**, початок одного запиту кожні
**0,5 секунди**. Інтервал спільний для всіх завантажень. Верхня межа — близько
**2 запитів/с або 120 повних карток/хв**, якщо кожен запит отримує нову картку.
Сторінки пошуку, час відповіді, недоступні вакансії та перевірки HH зменшують
фактичний результат. За вашими запусками більша паралельність не дала
стабільного прискорення; фактичний темп дивіться в метриках поточного запуску.

На скріншоті іншого парсера рахували 100 вакансій на сторінку. Перевірена
збережена сторінка пошуку HH містить 100 коротких записів без повних описів;
повні картки HH потребують окремих запитів. Тому 55–60 повних карток/с для
нашого збору не підтверджено.

## Запуск

Прочитати план без створення файлів та без мережі:

```powershell
.\.venv\Scripts\python.exe hh_fast.py
```

Коли інший збирач HH завершиться, продовжити незавершену чергу:

```powershell
.\.venv\Scripts\python.exe hh_fast.py --run --limit 20000 --max-requests 10000
```

Якщо черга вже закінчилася, повторно перевірити налаштовані пошуки на нові ID:

```powershell
.\.venv\Scripts\python.exe hh_fast.py --run --refresh-searches --limit 20000 --max-requests 10000
```

`--refresh-searches` перечитує сторінки пошуку, включно з раніше неповними;
готові картки повторно не завантажуються. Ця опція не додає нових роботодавців
або фраз і не усуває обмеження видачі HH. Після свіжого повного збору може
не знайти жодної нової вакансії.

Якщо HH попросить перевірку доступу:

```powershell
.\.venv\Scripts\python.exe hh_fast.py --manual-check
```

Після перевірки продовжувати командою `--run` без `--refresh-searches`.
Перевірки доступу не обходяться. За нестабільного доступу зменшіть темп:
`--workers 1 --delay 1.5`.

## Дані та повтори

- На першому запуску створюється окрема копія SQLite-черги у `data/hh_fast`.
  Основна база відкривається тільки для читання; браузерний профіль нового
  збирача також окремий.
- Уже готові картки перенесено локально, а їхні завантаження залишаються
  завершеними. Нові вакансії додаються за унікальним HH ID.
- На кожному наступному старті перевіряється, чи основний збирач завершив
  додаткові картки між запусками: ці ID також повторно не завантажуються.
- CSV/JSONL у `data/hh_fast` містять попередні та нові записи, по одному на ID.
  Це незалежний набір експортів. Нові картки швидкого збирача не записуються
  назад до основної бази: далі користуйтеся швидким файлом для продовження.
- Старі HTML залишаються у `data/hh_bulk/raw`; нові — у `data/hh_fast/raw`.
  Посилання на старі знімки в копії бази абсолютні: не видаляйте стару папку.
- Перед запуском перевіряються інші процеси `hh_bulk.py` / `hh_fast.py`.
  Якщо збирач працює або перевірити це неможливо, новий збір не стартує.
  Процеси не завершуються автоматично. Не запускайте основний збирач
  вручну після старту швидкого: початкова перевірка не контролює майбутні
  ручні запуски іншого файла.
- `--limit 20000` означає загальну кількість повних карток разом зі старими;
  `--max-requests` обмежує завантаження поточного запуску.

Реальний темп дивіться у `cards_per_minute` та `new_cards_this_run`.
Нуль нових карток під час перечитування вже зібраних пошуків не є помилкою.
